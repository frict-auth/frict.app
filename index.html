Frict privacy policy

Effective 2026-11-26

This privacy policy covers the Frict app for Android (app.frict.android), published by Geoffrey Freeman (“we”).

How Frict works

Frict approves sign-ins. The app on your phone holds one or more accounts, each paired with a Frict server. Each server is run by whoever manages your sign-in system, such as your employer, your school or someone in your household. We call them the operator. Frict’s server software is open source, and anyone can run it.

The operator, not us, runs the server and controls what it stores. Your accounts can be on servers run by different operators. We don’t run any server that receives your data. Your questions about a server’s data go to its operator.

What stays on your phone

  • Sign-in keys. For each account, the app creates two keys in Android’s secure key storage. The private halves never leave the phone.
  • Account settings. For each account: the server’s address, your Frict user ID, and whether approving accepts only your fingerprint or another strong biometric (such as face unlock on some phones), or also your screen lock.
  • Camera. If you scan the enrollment QR code, the app reads camera frames in memory to find the code. It does not save or send images. You can paste the link instead.
  • Biometrics and screen lock. Android checks your fingerprint or another strong biometric (such as face unlock on some phones), or your screen lock. The app only learns whether the check passed.

The app turns off Android backup and device-to-device transfer for its data. It has no ads, no analytics and no crash reporting.

What the app sends to Frict servers

Over HTTPS, to each account’s own server:

  • Your Frict user ID and the one-time activation code from the enrollment link.
  • The public halves of your two keys, with Android’s certificates for them (“key attestation”). These certificates describe the phone’s security: Android version, security patch level, whether the system software is verified, and which app made the keys. By default, the server uses them to check that the keys live in secure hardware and belong to the genuine Frict app.
  • Your phone’s Firebase installation ID (see Google, below), so the server can wake the app. Every server you add an account on gets the same ID.
  • The app’s version number, with every request, so the server can ask you to update an old version.
  • Your answers to sign-in requests: approve, deny, or “I didn’t start this”.

Like any web server, each server also sees your phone’s IP address and the standard information your phone sends with every web request.

When a wake-up message arrives and you have several accounts, the app asks your servers, in the order you added the accounts, for the sign-in request until one recognises it. A server that doesn’t recognise the request logs the attempt with your user ID on that server and your IP address, so its operator can tell that your phone was asked to approve a sign-in elsewhere.

The server gets from your sign-in system what the app then shows you: your username, the IP address the sign-in came from, the site name, and sometimes the application.

What the server keeps, by default

The operator can change these settings and decides on logs and backups.

  • Your enrollment (user ID, username, public keys, certificates, installation ID, app version) until you remove the account or the operator deletes it. If you never finish enrolling, the server deletes your username and user ID about 24 hours after the enrollment code expires.
  • Sign-in requests (username, IP address, site, your answer) for about 24 hours after each one expires. Then they are deleted automatically.
  • Service logs record events with your user ID, and your username when your enrollment is set up. When the server rejects a request, it also logs the IP address the request came from. The operator’s web server may log the IP address and request details of every request.
  • Backups and saved logs. If the operator deploys with the tool that comes with the server, each deploy backs up the server’s data and saves its service logs, and keeps those of the newest 5 deploys. Older ones are deleted.

Google

Google Play installs and updates the app under Google’s privacy policy.

Firebase Cloud Messaging, a Google service, wakes the app when a sign-in is waiting. For this:

  • The app gets a Firebase installation ID from Google, at the latest when you add an account. Google also receives the app version and basic device information: Android version, device model, brand and form factor.
  • Every wake-up message holds a random request number and nothing else. When one arrives, the app fetches the details from your server and shows a notification naming the account and server.

Google handles this data for us as a service provider, under the Firebase privacy and security terms. Google deletes installation IDs after about 270 days without use.

Removing an account

Remove this account in the app removes only that account; your other accounts stay. Its server first deletes your enrollment and your sign-in requests. Then the app deletes the account’s keys and settings on the phone.

If the server can’t be told, for example because it can’t be reached, you can still remove the account from the app. The server then keeps your enrollment until the operator deletes it.

Removing an account doesn’t delete these, which the operator controls:

  • the operator’s logs and backups, which keep your data until they are deleted
  • the records in your sign-in system

When you remove your last account, the app asks Google to delete its Firebase installation ID. Google then removes it from its live and backup systems within 180 days. While you still have an account, the ID is kept.

Sharing

We don’t sell data or share it with anyone. The app sends data only to the Frict servers you added accounts on and to Google for push messages.

Security

  • All network traffic uses HTTPS.
  • The app signs every request with a key kept in secure hardware.
  • An approval needs your fingerprint or another strong biometric (such as face unlock on some phones), or your screen lock if you allowed it.
